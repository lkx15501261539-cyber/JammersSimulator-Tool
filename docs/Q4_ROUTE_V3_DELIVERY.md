## 运行

Mac双击仓库或新统一交付目录中的`启动界面.command`；Windows双击`启动界面.bat`。
在同一个模型菜单选择“第四问 · 路径约束机会复测 · v3.0”。预算和绕路秒数可在窗口设置。
旧版独立入口继续选择其原版本；旧压缩包不会自动获得本轮模型，应用默认也不会因为
论文建议而自动变成预算1。Mac共用现有本地依赖环境，具体见[Mac启动说明](../Mac启动说明.txt)。

在装有`requirements-q3-v2.txt`的Python环境中，可运行问题4并保存回放：

```sh
python -m enhanced q4 --model q4_route_v3 --problem 4 --seed 42 --scenario uniform --error-model worst_edge --extra-budget 2 --tau-route 5 --output runs/q4-route-42
```

本批T优先的手动设置只需将`--extra-budget 2`改为`--extra-budget 1`。HTTP运行方法见
[模型说明](Q4_ROUTE_V3.md#运行与交付)。新策略用于全向协议测试可指定`--problem 3`，
这不会替换Q3七点法。复制实验需一个全新的输出目录：

```sh
python tools/q4_compare.py --jobs 4 --output experiments/q4-route-new-run.json --plots
```

默认重跑30×7矩阵。图表另需`matplotlib`，不把它加入GUI必要依赖。CLI支持指定
`--variants`、`--seeds`、`--distributions`；`--full-grid`为30×11，未计入本页已完成结果。
既有矩阵文件名与源文件哈希保存在分析JSON；大型原始回放与完整矩阵没有复制进仓库。

## 主要结论与是否最优

预算2、τ5相对旧v2在30场全部更快，场均T从13957.76降到9359.50秒；平均T相对降低32.94%，
逐场百分比的平均为32.31%。相对主动Q2仅21场更快、9场更慢，最差repulsive seed45慢18.38%。
应用默认不变；七个已测配置中，预算1、τ5的场均T最小，为9175.09秒。预算2降低光学尝试，
但在本批总T上没有赢过预算1。τ20相对5的平均收益仅0.47%，21场相同，不能据此认定普遍更优。

代码能执行连续距离/清除证书以及有限预算，不意味着整个闭环任务是最优解。
路线内选择使用有限候选、有限误差与位置样本；`Jhat`不是连续最坏损失上界。
完整计划使用声明的保守C/U费用和有限轮局部调整，不是穷尽所有反馈策略的全局优化。
实际机器人任务时间T与CPU/墙钟分开计量；候选边际绕路之和不能当作完整任务时间。

预算2、τ5将完全不复测源从360降至16，但有123/344个实际复测源仍等待超过1小时，
最大等待约186.55分钟；其中预约很早、执行很晚的现象明确存在。本版不能宣称
“正常情况都会迅速再测”。达到预算、连续失联或没有可执行机会后进入原U，
不以no_signal删未经证明的F，也不将FOUND标为ABSENT。

有限停止依赖有限搜索、有限预算和严格减少的光学待执行序列；它没有给出任意场景
在360000虚拟秒内完成的统一证明。仍未覆盖所有几何、所有合法误差场、所有参数组合，
也未建立任意场景更快、连续Q2全局最优或默认参数普适最优的结论。
