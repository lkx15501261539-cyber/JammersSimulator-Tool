# 原模型路线、迭代次数与规划队列观察

本功能显示 Baseline 1.0 原模型在任务当时已经确定的信息。原始 ZIP、`run.py`、
`solver.py`、`第一问.py` 和 `config.json` 保持不变；观察层不调用额外规划求解，
不替模型挑选目标，也不使用世界真值补全未知坐标。

## 原模型实际如何排任务

两个模型共用原 Controller，区别在固定路线配置：六边形 7 点或螺旋 12 点。
控制器依次执行固定测点，在每一段路线中最多插入一个目标服务；候选服务由原模型
的测点规划与绕行代价选择。固定测点执行完后，控制器才创建真实的尾扫列表，按原模型
记录的发现次序执行剩余目标。

因此，模型中不存在一份从任务开始就确定的“全部目标优先队列”。界面将以下信息分开：

- **当前目标**：原模型已经选定的当前测量或清除动作，以及实际请求中的频道、坐标。
  开始移动之前便记录该输入，移动、切频和检测期间都能查看它。
- **任务队列**：当前已选定动作及剩余固定测点。后续路线段可能再由原模型插入服务，
  这些尚未选定的动作不会提前编进队列。进入尾扫后显示原 Controller 已经创建的
  实际尾扫顺序。
- **待调度目标**：原模型当前处于 `FOUND`、且不是正在服务的频道。这些目标尚未
  形成全局执行顺序，不能把显示顺序理解为优先级。
- **候选测点**：原模型实际 `get_plan()` 调用返回的已知方案。候选方案不等于最终
  选中方案，也不表示已经承诺执行。

尚未规划的目标坐标保持空值，并显示“尚未规划”一类提示。未来尾扫任务即使有曾经
计算出的候选点，也不会将该候选点伪装成已经确定的执行坐标。

## 固定测点与“已走过”

固定路线坐标直接来自原配置 `points`，编号沿用配置中的顺序。记录中使用从 0 开始的
`index`；界面可以按人类习惯显示为从 1 开始的序号。

`visited` 由回放时刻已经执行的路径判断：起点在时间 0 已到达；后续点只有在机器狗
实际到达或沿已执行线段经过该点后才变为已访问。判定使用 1e-6 m 数值容差。
已经决定去某个点、或者已经开始向该点移动，都不会提前将其标为已访问。
时间轴向后拖动时，访问状态按那一时刻重新计算。

访问状态表示空间路径经过，不等于“该点全部频道已经扫描完毕”。机器狗抵达固定点
后可能仍在完成该点的一组测量，当前动作和任务状态会继续显示这一过程。

## 每个源的迭代次数

`channel_iterations` 按频道记录两个独立计数：

| 字段 | 含义 |
|---|---|
| `followups` | 原模型 `Channel.followups`，只累计 `target_followup` 角色的补充检测；包含补充检测得到 `no_signal` 的情况 |
| `limit` | 原配置 `max_followups`，当前原包中为 5；不因路线段改变而重置 |
| `measurements` | 该频道所有已经完成的原模型测量，包括固定测点扫描与补充检测 |
| `state` | 原模型频道状态，如 `UNKNOWN`、`FOUND`、`CLEARED`、`UNRESOLVED`、`EMPTY_CERTIFIED` |
| `discovery` | 原模型记录的发现序号；未发现时为 -1 |

两种计数均在原动作完成后更新。补充检测迭代数不等于全部测量次数，也不计入单独的
清除动作。原模型已有的迭代上限与停止条件均保持原样。

## 记录与接口

`enhanced/strategy_observer.py` 在模型子进程中临时包裹原 Controller 方法，原方法仍
接收原参数、执行原计算并返回原结果。观察层只复制返回的方案和原 Controller 状态；
实际尾扫顺序直接读取原 `Controller.run()` 已经构造的 `tail` 列表，不重写排序规则。
原代码的 `decisions.json` 不由观察层改写。

模型子进程通过独立的 `strategy_state` 消息把观察快照发给父进程。父进程在当前虚拟
时间追加零时长的 `StrategyState` 事件到 `events.jsonl`。规划快照不发回策略，不进入
`/enter`、`/measure`、`/clear`、`/exit` 的响应，也不影响动作计时。

回放提供 `state['strategy']`：

```text
available: true / false
schema_version: 1
route_name: 原配置路线名
route_points: [{index, position: [x, y], visited}]
current_anchor: 原模型当前固定测点下标
phase: starting / anchor_scan / planning / route / service / tail / finished
current_target: {kind, channel, position: [x, y], role} 或 null
tasks: [{kind, channel?, anchor_index?, position: [x, y] 或 null,
         coordinate_status: fixed / planned / not_planned}]
queue_kind: anchor_scan / route / tail / finished
queue_note: 说明固定路线、每段插入与尾扫的关系
pending_targets: [{channel, followups, discovery, position 或 null,
                   coordinate_status: candidate / not_planned}]
candidates: [{channel, kind, position: [x, y]}]
channel_iterations: {频道字符串: {followups, limit, state, measurements, discovery}}
```

`state['route_points']` 同时提供固定测点列表，便于地图直接使用。日志中的原始
`StrategyState.route_points` 不保存推测访问状态；`visited` 在回放投影时根据已执行
轨迹补充。回放只采用当前时刻已出现的最后一份快照，不扫描未来规划来填补信息。

## 旧日志

此前保存的日志若没有 `StrategyState`，仍然能够正常播放原有动作、轨迹和定位。
规划观察字段为 `available: false`，并明确说明“此日志未记录原模型的规划状态”。
固定路线列表、队列、逐频道迭代状态和当前规划目标不会根据未来动作反推生成。
要查看这些新字段，需要使用原 ZIP 重新运行一局，或载入包含新事件的日志。

## 本轮后端验证

`tests/test_strategy_observer.py` 覆盖以下 6 项验证：

1. 固定点只有在实际经过后改变访问状态，支持中途穿过测点与向后回放；未完成补充检测
   不提前增加迭代次数。
2. 旧日志明确返回规划信息不可用，不编造队列或计数。
3. 六边形模型在相同 seed 42 场景下，原执行与启用观察层的执行逐项相同。
4. 螺旋模型进行相同的完整任务对比。
5. 实际子进程 → 父进程 → 保存日志 → Replay 全链路保存规划快照，末态迭代计数和
   频道状态与原模型 `summary.json` 一致。
6. 原模型收到 `near` 后会在同一次 `measure()` 调用内继续清除；清除尚未完成时，
   已完成测量和补充检测计数已更新，但清除状态仍保持待完成。

两模型的完整任务等价验证比较了所有请求与响应、原始 `decisions.json`、模型摘要和
模拟器统计。仅将随机 `request_id` 从请求比较中排除，并从摘要比较中排除墙钟运行耗时。
两次执行均为 15 / 15 清除；原模型源文件与配置的哈希校验一致。测试还核验了原方法
恢复、真正尾扫顺序、实际请求目标坐标，以及快照不携带示向结果或世界真值。

这些验证证明新增观察层没有改变所测任务的原模型执行，不构成所有 seed 都能全清除
的保证，也不新增任何第三问规划策略。Windows 实机验证仍未完成。

## 当前界面与本机验收

- 浅色地图；固定测点显示 P1–Pn，未到访蓝色、已到访绿色。干扰源未清除橙色，
  清除后绿色并带勾；检测点 D1、D2…与固定点使用不同标记。
- 默认统一 **1×**。走路、扫描、切频、清除不自动变速；手动倍速对所有动作统一生效。
- 触控板双指平移，捏合或 Ctrl / Command + 滑动缩放；另有 + / − 按钮、缩放条和全域复位。
  相机保留小数位移，连续小幅操作、缩放锚点和窗口调整不会累积跳动。
- 右侧同时显示当前任务坐标、实际执行队列、待调度目标和各源追加测点次数；完整遥测
  在“完整指标”标签。当前频道行突出显示，列名保留在滚动区外。
- 独立定位详图包括测点示向总览、交汇区域放大、检测坐标和角度。进入已有测向的目标
  任务后自动展开；成功清除后收起。清除失败会保留详情，直到切换目标或任务结束。
  手动关闭后可点击“定位详图”重新打开；回放拖动按所选时刻恢复。
- 原生 macOS 验收发现 Qt 单元格表格的辅助功能路径会崩溃，现已替换为两个持久的
  只读文本表格；保留数据、选择、滚动和当前目标提示，没有关闭系统辅助功能。
