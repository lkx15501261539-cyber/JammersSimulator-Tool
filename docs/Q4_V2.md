# 第四问 v2.0：左右机会复测

Q4 v2.0 按《第四问 机会型左右复测 方案》接入统一模拟器，保留 Q4 v1.0 供同场景比较。
新模型标识为 `q4_opportunity_v2`；旧模型标识仍为 `q4_cu`。
Q3 六边形 1.0、螺旋 1.0、七点六边形 2.0 的原始模型包及核心代码不变。

## 本版范围

沿用原来的 25 点搜索、Q1 几何、Q2 候选测点和 C/U 光学收尾模块，在尚未访问的
搜索点上附加已发现频道的左右复测任务。机会点不额外增加空间节点；先按左右点中
较晚一个在剩余路线中的位置排序，再比较保守交会质量及附加任务数量。序号与质量相同时，优先取整个 F 上均处于 30°–60° 的点对。
有合法机会对时优先执行文稿的机会流程，无合法机会对时退回原 C4/U 决策。

安全左侧或右侧返回 `no_signal` 时，只有已认证的整对条件仍有效且已预留对侧
次数，才将对侧作为保证复测任务保留；允许有限位置的单节点 Or-opt 前移，并按
包含实际换频的计划成本比较是否接受。同轮多个频道共享同一对侧点时按节点去重，
避免前移窗口被重复累加。普通未认证失联继续执行保存的光学后备，
不得据此删除附近的候选源位置，也不得把已发现频道改成 ABSENT。

`direction` 更新原来的 `F_k^ell/P_k^ell/E_k^ell` 并重规划；`near` 原地清除。
无线电信息仍不足或次数用尽时，执行覆盖完整 `F` 的 20 米光学收尾。

## 仅落实必要修正

- 搜索坐标保留已认证的内圈 980 米、外圈 1880 米、外层错开 15°；不用文稿的
  极限半径直接取整，以避免破坏边界发现保证。证书针对实际使用的搜索坐标。
- 频道首次 `direction` 后保留三次追加测向预算 `r_k=3`。追加的每次实际测量
  都扣一次，包括 `no_signal`；普通左右对至少预留两次，失联后为对侧保留一次。
- 安全距离和左右角条件必须覆盖整个位置可行域；实现使用保守认证，不能把若干
  采样点通过当成全域证明。认证不通过时拒绝该候选对，仍可光学收尾。
- 计时沿用实际动作累计：`T = L_move/5 + N_sw + 5*N_meas + 3*N_clr + 2*N_succ`。
  插入测量后若还要切回原频道，两次换频均计入。
- `ell` 仍是信息更新序号，`r_k` 仍是剩余追加次数；不将文稿的半径下界记号
  `r_k^-` 覆盖到次数变量上。`P` 仍为纯测向楔形交，`F` 融合物理约束，`E` 为认证外包。

存在性扫描只针对 UNKNOWN；FOUND 的机会复测有独立记录。只有 UNKNOWN 频道在
25 个搜索点都实际测量且均 `no_signal` 才标 ABSENT。成功清除 16 个不同频道可
按源总数上限提前结束；否则需完成必要存在性检查并清除所有已发现源。

## 运行与版本切换

完整解压后，窗口的“模型”下拉框可在已经整合的模型间切换。每个解压目录是独立
副本；旧目录不会自动获得新模型。Q3 1.0 的两个模型需要原始两模型 ZIP。

| 平台 | Q4 v1.0 | Q4 v2.0 |
| --- | --- | --- |
| macOS | `start_q4.command` | `start_q4_v2.command` |
| Windows | `start_q4.bat` | `start_q4_v2.bat` |

新入口共用原环境准备逻辑，Q4 模型无新增第三方依赖。已有环境中可执行：

```sh
python -m enhanced gui --problem 4 --model q4_opportunity_v2 --error-model worst_edge
```

两个平台的新入口均支持 `--check-only`，核验所选 Q4 v2 模型和离屏窗口后退出。
Windows 也可运行 `start_q4.bat --v2 --check-only`；无 `--v2` 的旧入口仍选择 v1。
完整环境说明见 [模型启动入口](MODEL_LAUNCHERS.md)。

## 保留的限制

这次没有重做底层 C4 的方向观测分箱或自适应信息收益上界。无机会对时沿用的旧
C4/U 评价仍较保守；不能据“至少一侧可见”断言总时间一定优于 v1。
机会对认证采取保守条件，可能拒绝实际可用的点对；这会影响成绩，不影响光学兜底。
全场景性能优劣需用相同种子、场景和误差规则对照实验评价。

本文件不将以往 Windows v1 的测试记录当作 v2 验证。v2 的具体测试结果及所测
平台应以本次测试产物为准；尚未运行的平台和官方比赛服务不得表述为已验证。

本次 Windows 实测已通过：[CI 运行记录](https://github.com/lkx15501261539-cyber/JammersSimulator-Tool/actions/runs/34696331584)，
所测源码提交为 `5278c429e583cd86cac3ff56c879b41f880616de`。
Windows Server 2025 x64 / Python 3.12.10，中文及空格目录：四个 BAT 正常启动入口
均出现正确版本的原生可见窗口并正常退出，包含 Q4 v2；接口与打包测试 82 通过、
8 跳过，Q4 v1/v2 核心测试 50 通过。跳过项为 6 个 Mac zsh 检查及 2 个依赖外部
Q1 演示引用的测试。[结构化证据](Q4_V2_WINDOWS.json) 保留窗口标题与退出码。
这验证了该 Windows 环境，不代表所有 Windows 版本和用户环境均已验证。

## 为什么首次发现后可能没有可用机会对

首次示向度留下的 F 同时包含近端和远端源位置。点对必须对整个 F 满足安全距离、
左右分布和角宽不超过 180°；围绕估计中心看起来合适的两个点可能不能通过认证。
例如 S0=(0,0)、示向度 0° 时，真实位置 g=(10,0) 仍可行。内圈两点
(848.705,490)、(848.705,-490) 相对于 S0−g 的偏角约为 −149.705° 与
149.705°，角宽约 299.410°。源若朝正西，S0 可见而两个点均在背面。
这是必须拒绝的一对真实反例，提高外包精度不能消除；它不证明所有场景都无机会对。
代码已排除 E 错误保留首次测点的伪退化，同时保留真正的 5.001m 近端源。

无合法机会对时，当前保守 C4 也不会主动产生一次用于缩小 F 的额外测向。
因此下一轮若希望机会复测在普通场景频繁触发，需要另行评估启动条件或主动测向
策略；本次按已批准范围交付，没有擅自改变保证条件或重做 C4。

尚未证明任意允许场景下的成绩优势、全局最优及在模拟器 360000 秒任务上限内
一定完成。调度用于抵消未来未知源影响的公共光学松界可能超过该上限，它只用于
候选排序，不能作为限时可执行证明。连续发现与几何覆盖证书不等同于限时完成证明。
未接入官方比赛服务；真实 Windows v2 的验证状态由本次 CI 记录单独说明。
